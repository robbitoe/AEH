AEH 1.1.0 can run every agent in a container: set `sandbox.agent_image` to turn it on (upgrading alone changes nothing, and without it agents run on the host as in 1.0.0). Agents then get no network besides the hosts their profile declares, see only the files their step needs, and keep their CLI logins between launches without access to your home directory.

New to AEH? Read the [getting started guide](https://github.com/robbitoe/aeh/blob/v1.1.0/docs/getting-started.md). Setting up the sandbox: [docs/sandbox.md](https://github.com/robbitoe/aeh/blob/v1.1.0/docs/sandbox.md).

## What is new

- **Agents in containers** (`sandbox.agent_image`). Implementers, reviewers, triage, test and characterization authors, discovery authors, book reviewers and adoption inspectors each run in a container from an image you build. Each sees only what its step needs: a copy of the commit at `/work` (writable for implementers and authors, read-only for reviewers), product memory read-only at `/memory`, and an output directory when the step writes documents. Nothing an agent writes is checked out on the host: aeh reads the implementer's work back from the container and records it as a commit from Git objects.
- **Declared hosts only** (`sandbox.egress`). Agent containers have no network. For each launch, aeh starts a proxy container, the only one with a network, that allows `CONNECT` to the profile's exact `host:port` pairs, resolves names itself and refuses private, loopback and metadata addresses. The proxy logs to `<log>.egress.log` one line per tunnel (host, port, bytes and verdict; every tunnel is recorded) and one per refusal, with the host and port when the request named a valid target. Refusal lines stop after 10,000 per launch, with a line saying so. The proxy is `aeh-egress`, a second, standard-library program built into the agent image from this repository (`docs/sandbox/Dockerfile.agents`).
- **Kept logins** (`sandbox.session`, `aeh sandbox login <profile>`). A profile that signs in with a subscription logs in once inside the agent image; aeh keeps only the declared files, privately, under `.aeh/sandbox/sessions/`, and copies them into each launch's empty `HOME`.
- **Profiles' own variables** (`sandbox.pass_env`). The project's `pass_env` is never forwarded to agent containers; each profile names the host variables it receives (for example an API key or `CLAUDE_CODE_OAUTH_TOKEN`).
- `aeh sandbox check` also checks the agent image and warns about missing programs, profiles without egress, declared sessions with no saved login, and Codex profiles that ask for Codex's own sandbox, which cannot run in a container (use `--sandbox danger-full-access` there; the container is the sandbox).

## Measured

On Windows with Docker Desktop, a real plan and run of a small feature with every agent in a container took 97 s and 54 s, each accepted on its first attempt, with independent reviews from the other provider. A hostile test agent reached only its declared host: no DNS, no route to the internet, gateway, host or metadata, a read-only root and no Docker socket. Claude Code needed only `api.anthropic.com:443`; Codex, `chatgpt.com:443` (and `auth.openai.com:443` to log in).

## Upgrading

Runs and plans pin their sandbox policy. A configuration you do not change (no sandbox, or gates only) keeps working with runs and plans started under 1.0.0. Turning on `sandbox.agent_image` changes the policy: blocked runs and reserved plans started before it do not resume and need a new outcome or plan.

## Install

Download the archive for your system below, check it against `checksums.txt`, and put `aeh` on your `PATH`. Or, with Go 1.24+:

```sh
go install github.com/robbitoe/aeh/cmd/aeh@v1.1.0
```

## Known limitations

- Tested on Windows and Linux; macOS builds but has not been tested.
- Without `sandbox.agent_image`, agent CLIs run with your user's permissions, limited only by their own sandbox flags.
- `aeh do` cannot resume after a block, except one that paused with a `SPEC-QUESTION`.
- A CLI that reports its usage limit only in its message (Claude Code exits 1 with "You've hit your 5-hour limit") is not yet recognized as a quota signal: its attempts count as failures. Rerun after the limit resets. Recognizing it is the next change.
- Local HTTP providers on the host (LM Studio) are not supported inside the agent sandbox.
